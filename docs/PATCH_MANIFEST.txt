## Consolidated behavior in this revision
- Cloudinary URL identity requires HTTPS, `res.cloudinary.com`, exact configured `cloudinary.cloud-name`, safe URL path, the managed `aloute/` folder, exact ledger URL, expected purpose/resource type, and authenticated uploader.
- Upload endpoint and direct user-avatar endpoint share Redis per-user rate limiting (30 uploads/hour; 15-minute block after the threshold). Required Redis outages fail closed for rate limits.
- Document/raw upload is disabled in both controller and storage layers until a dedicated scanner is added. Legacy raw delivery URLs may still be parsed for cleanup only.
- Upload-purpose policies are centralized in `UploadPurpose`; post media is moderated by the post worker after persistence, while chat/community/avatar/general image/video upload is checked before a public URL is returned when moderation is enabled. Non-post upload fails closed if moderation is disabled/unavailable.
- `MediaAssetLifecycleService` is the single lifecycle owner for post, chat, community, avatar, and account cleanup; it tracks uploader/purpose/reference, retries failed Cloudinary deletion, invalidates CDN delivery, and retains tombstones to prevent approving posts whose media was deleted.
- Orphan scans select aged `UPLOADED` items and `DELETE_PENDING` items only; `ATTACHED` media is not repeatedly scanned. `postId` is stored when available.
- Admin APPROVE is rejected when the post's tracked media was deleted or is pending deletion; replacement media should be uploaded and submitted in a new post.
- Redis cache failures are fail-open (cache is an optimization). Security rate limiting remains independent and fail-closed when configured as required. Online presence uses Redis session leases with same-node fallback when Redis is unavailable.
- Docker Compose/Coturn provisioning remains intentionally deferred to the group's deployment phase. Backend TURN credential generation does not mean a real TURN server is present. Multi-instance STOMP fan-out still requires broker relay infrastructure.
- Exactly one migration document is kept at `docs/DATABASE_MIGRATIONS.md`; the only patch manifest is `docs/PATCH_MANIFEST.txt`.

## Safety exclusions
- No real `.env`, `.secret/`, Firebase Admin credential JSON, `.git/`, `target/`, `__pycache__/`, `.pyc`, `.class`, or local logs are included in generated archives.
- This manifest lists files to delete from the base. Applying the delta patch does not automatically delete removed paths; delete those exact paths manually after confirming the base revision. Prefer the full source ZIP to avoid this manual step.
